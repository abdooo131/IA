# Agents & Fleet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The agents module and the Agents & Fleet app: agent companies with rates, their people (one record, one login) and vehicles, documents and compliance that block people until fixed, requests for extra people or vehicles, truck routes, one settlement per agent per period for both companies (less the cash its people hold) that becomes a bill when the agent's invoice arrives, and the agent's own screen.

**Architecture:** Module `agents` with its own schema. It owns people: parcels asks `AgentsService.canWork(userId)` before a pickup is assigned or a run starts. Agents learns the work done from parcels events (`parcel.status_changed` with the courier, `pickup.started`, `car.departed`) into its own work log, so settlements never read another module's tables. Money gets the settlement as a bill through a new public `MoneyService.createBill`.

**Tech Stack:** as before.

**Spec:** `shiply/docs/UI.md` Step 3g (and its changes to Shiply and Accounting), Step 3c item 3 (agent bills need the agent's invoice), Step 4 item 5 (agent screen); `shiply/docs/TECH.md` sections 3 and 4.

## Global Constraints

- Everything in the earlier plans' constraints still applies.
- Every driver, courier, rider and pickup person belongs to one agent; one person, one record, one login (`kind: agent_person`, role `field`). Agent managers log in with `kind: agent_manager` and see only their own agent.
- A person works only while `approved` and not blocked. A required document (national ID and driving licence for every role; vehicle licence and insurance for a vehicle) that is missing or expired blocks the person until fixed.
- Rates are piastres: `perDelivery`, `perPickup`, `perTrip`, `perRiderOrder`.
- Settlement: one per agent per period, both companies, lines per company and kind; net = work − cash its people hold; draft → approved (a second person with `fleet` manage, never the preparer) → billed when the agent's invoice number is entered (becomes a money bill to account 5101, payee the agent).
- Access: app `fleet`: view to see, use to prepare, manage to approve and to approve people.
- Courier zones stay in parcels (ledgered ruling of the parcels plan).

## Review Focus

1. A blocked or not yet approved person assigned a pickup or a run: refused with `person_cannot_work`.
2. A document renewed after it expired: the person is unblocked by the next check, not before the new expiry is entered.
3. The same delivery counted twice in a settlement (event delivered twice): counted once (work log keyed by source).
4. Two settlements for one agent with overlapping periods: refused with `overlapping_period`.
5. An agent manager reading another agent's people, requests or settlement: 404.

### Task 1: Agents, people and the work gate

**Files:** schema `agents` + migration; `apps/api/src/agents/{index.ts, agents.module.ts, agents.service.ts, agents.controller.ts, people.controller.ts}`; parcels `runs.service.ts` and `pickups.controller.ts` call `canWork`; `app.ts`; test `apps/api/test/agents.test.ts`

**Interfaces:**
- Models: `Agent(id, code unique, name, nameAr, contactName, phone, services String[], perDelivery Int, perPickup Int, perTrip Int, perRiderOrder Int, active)`; `AgentManager(userId @id, agentId)`; `Person(id, agentId, userId unique, role: delivery|pickup|rider|truck_driver, nationalId?, status: pending|approved|rejected, blocked Bool, blockedReason?, createdById, approvedById?)`.
- `AgentsService.canWork(userId) → boolean` (approved, not blocked, agent active); `personOf(userId)`.
- Routes (`fleet`): `GET/POST/PATCH /agents`, `GET /agents/:id`; `GET /agents/people?agent&status&q`, `POST /agents/people {agentId, role, name, nameAr, mobile, password, nationalId?}` (makes the login with `createLogin`, kind `agent_person`, role `field`), `POST /agents/people/:id/approve` (manage, not the creator), `POST /agents/people/:id/reject {reason}`, `POST /agents/managers {agentId, name, nameAr, email|mobile, password}` (login kind `agent_manager`, role `field`).
- Parcels: `POST /parcels/pickups/:id/assign` and `POST /parcels/runs` refuse with 400 `person_cannot_work` when `canWork` is false.

- [ ] Tests: a person created by one admin cannot be approved by the same admin (403 `own_person`), a second admin approves; a pending person cannot get a run (`person_cannot_work`), an approved one can; an inactive agent's person cannot; creating a person with a taken mobile → 409 `login_taken`.
- [ ] RED → implement → GREEN → commit `feat(agents): agents, people and the work gate`.

### Task 2: Vehicles, documents and compliance

**Files:** `apps/api/src/agents/{vehicles.controller.ts, compliance.service.ts, compliance.controller.ts}`; test `apps/api/test/compliance.test.ts`

**Interfaces:**
- Models: `Vehicle(id, agentId, plate unique, type: motorbike|car|van|truck, capacityKg Int?, personId?, active)`; `Document(id, personId?, vehicleId?, kind: national_id|driving_licence|vehicle_licence|insurance|criminal_record, number, expiresAt Date?, createdById, createdAt)`.
- Plates normalised (Arabic letters and digits kept, spaces removed, upper case) and unique.
- `ComplianceService.check(now)`: for every approved person, missing or expired required documents (national ID and driving licence; for a person with an active vehicle: its vehicle licence and insurance) → `blocked = true`, `blockedReason` lists them, publishes `agents.person_blocked`; a blocked person whose documents are now all valid → unblocked. Runs daily (worker every hour) and after each document change for that person.
- Setting `agents.expiry_warning_days` (default 30). `GET /agents/compliance` lists expired and expiring documents with person and agent. Home attention `home.documentsExpiring` for fleet use.
- Routes: `GET/POST/PATCH /agents/vehicles`, `POST /agents/documents`, `GET /agents/people/:id` (with documents, vehicle, blocked reason).

- [ ] Tests: an approved person without a driving licence is blocked by `check`; entering a licence that expires next year unblocks on the next check; an expired insurance on his vehicle blocks him again; documents expiring within 30 days are listed and counted on Home; a duplicate plate written with spaces → 409 `plate_taken`.
- [ ] RED → implement → GREEN → commit `feat(agents): vehicles, documents and compliance`.

### Task 3: Requests, truck routes and the work log

**Files:** `apps/api/src/agents/{requests.controller.ts, routes.controller.ts, worklog.service.ts}`; parcels events: `parcel.status_changed` payload gains `courierId`, new `pickup.started {pickupId, courierId}` (when a pickup becomes on the way), `car.departed {carId, routeId?}`; parcels `Car` gains `routeId?`; test `apps/api/test/requests.test.ts`

**Interfaces:**
- Models: `Request(id, siteId, date Date, role, count Int, vehicleType?, note?, agentId?, status: open|confirmed|declined|cancelled, requestedById, answeredById?, answeredAt?)`; `TruckRoute(id, code unique, fromSiteId, toSiteId, departAt "HH:MM", agentId, vehicleId?, active)`; `WorkLog(id, sourceKey unique, agentId, personUserId?, kind: delivery|pickup|trip|rider_order, companyKey, at)`.
- Requests: `POST /agents/requests` (fleet use, or shiply use for a hub), `GET /agents/requests?status&site`, agent manager `POST /agents/me/requests/:id/confirm` and `/decline` (only requests sent to his agent or to any agent; once).
- Truck routes: `GET/POST/PATCH /agents/routes`; parcels `POST /parcels/cars` accepts `routeId` (fills from, to and the agent's driver name).
- Work log handlers (all keyed so a repeated event counts once): delivered parcel → `delivery` for the courier's agent; `pickup.started` → `pickup`; `car.departed` with a route → `trip` for the route's agent.

- [ ] Tests: an agent manager confirms a request once (second → 409) and cannot see another agent's request (404); a delivered parcel writes one delivery to the work log even when its event is processed twice; a car made from a route writes one trip for the route's agent when it departs.
- [ ] RED → implement → GREEN → commit `feat(agents): requests, truck routes and the work log`.

### Task 4: Settlements

**Files:** `apps/api/src/agents/{settlements.service.ts, settlements.controller.ts}`; `apps/api/src/money/{money.service.ts (new public MoneyService), index.ts}`; test `apps/api/test/settlements.test.ts`

**Interfaces:**
- Model: `Settlement(id, agentId, from Date, to Date, lines Json [{companyKey, kind, count, rate, amount}], gross Int, cashHeld Int, net Int, status: draft|approved|billed|cancelled, preparedById, approvedById?, invoiceNumber?, billIds String[])`.
- `POST /agents/settlements {agentId, from, to}` (fleet use): counts the work log in the period × the agent's rates per company; `cashHeld` = cash its people hold now (`CashService.heldBy` for courier and rider holders of its people); refuses `overlapping_period`.
- `POST /agents/settlements/:id/approve` (manage, not the preparer); `POST /agents/settlements/:id/invoice {invoiceNumber}` (use, approved only, once) → `MoneyService.createBill(tx, {companyKey, payee: agent name, number, date, dueDate (+15 days), amount, vat 0, accountCode '5101', preparedById})` one bill per company with work, status `draft` so money's second person approval still applies; the settlement is `billed`.
- Agent manager: `GET /agents/me/settlements` (his own only).

- [ ] Tests: 3 deliveries and 1 pickup in the period with rates 20 EGP and 15 EGP → gross 75 EGP; a courier of the agent holding 250 EGP → net −175 EGP; the preparer cannot approve; the invoice makes one draft bill of 75 EGP in money for Shiply; an overlapping second settlement → 409.
- [ ] RED → implement → GREEN → commit `feat(agents): settlements`.
