# Put Shiply Now online (free staging, no credit card)

Two free services:

- **Neon** hosts the PostgreSQL database (PostGIS is supported).
- **Render** builds this repository's `Dockerfile` and runs the API and the website in one
  container, with https.

Free plans change. Check each sign up page; at the time of writing neither asked for a card.

Limits of the free setup: Render puts the service to sleep after about 15 minutes without
visits, and the first visit after that takes 30 to 60 seconds. That is fine for testing and
demos. Live Shopify orders (Step 5) need a paid always on plan.

## 1. Database on Neon (5 minutes)

1. Sign up at https://neon.tech (GitHub sign in is fine).
2. Create a project: name `shiplynow`, Postgres version **16**, region **AWS Europe (Frankfurt)**.
3. On the project dashboard click **Connect**. Turn **Connection pooling off**, and copy the
   connection string. It looks like
   `postgresql://USER:PASSWORD@ep-something.eu-central-1.aws.neon.tech/neondb?sslmode=require`
4. Keep it private. It goes only into Render's settings in step 2, never into the code or a chat.

You do not need to create tables or install PostGIS: the server does both on its first start.

## 2. Website and API on Render (10 minutes, then about 10 minutes of building)

1. Sign up at https://render.com with your GitHub account and allow it to see the
   `abdooo131/IA` repository.
2. Click **New**, then **Blueprint**, and choose the `abdooo131/IA` repository.
   - If Render asks for a branch, pick `ShiplyNow` (or `main` once the work is merged).
3. Render reads `render.yaml` and shows one free web service called `shiplynow`. Fill in:

   | Setting | What to enter |
   | --- | --- |
   | `DATABASE_URL` | the Neon connection string from step 1 |
   | `SEED_ADMIN_EMAIL` | the admin login you want, for example `admin@yourcompany.com` |
   | `SEED_ADMIN_PASSWORD` | a strong password, at least 10 characters |
   | `SEED_DEMO_PASSWORD` | password for the demo staff, rider and merchant accounts |
   | `GOOGLE_MAPS_API_KEY` | leave empty unless you have one |
   | `SHOPIFY_API_SECRET` | the Shopify app's client secret (Dev Dashboard), only when testing Shopify |

   `JWT_ACCESS_SECRET` is generated by Render automatically. Do not change it later, or
   everyone is signed out.
4. Click **Apply**. The first build takes around 10 minutes. Watch **Logs**; it is ready when
   you see `starting API ... and web ...`.
5. Open the address Render shows, like `https://shiplynow.onrender.com`, and sign in with the
   admin email and password from step 3.

Every push to the branch rebuilds and redeploys automatically.

### Phone notifications (web push, optional)

Without these three variables nothing is sent and the Notifications page says it is not set up.

1. On any computer with Node.js, make one key pair:

   ```bash
   npx web-push@3.6.7 generate-vapid-keys
   ```

2. In Render, open the `shiplynow` service, **Environment**, and add:

   | Setting | What to enter |
   | --- | --- |
   | `VAPID_PUBLIC_KEY` | the Public Key line (not secret) |
   | `VAPID_PRIVATE_KEY` | the Private Key line (secret: never in git or a chat) |
   | `VAPID_SUBJECT` | `mailto:` and an address the push services may write to, for example `mailto:ops@yourcompany.com` |

3. Save; Render redeploys. Every person then opens Settings menu, Notifications, and turns
   them on for each phone (iPhone: add to the Home Screen first, iOS 16.4 or later).

Keep the same pair for good: a new pair silently stops every device until each person turns
notifications on again. The `push.enabled` setting (Settings, System) switches sending off
without removing the keys.

## 3. Using it

- It is https, so the **phone camera** works for scanning.
- Demo accounts (password = `SEED_DEMO_PASSWORD`):
  `staff.newcairo@shiplynow.local`, `staff.maadi@shiplynow.local`,
  `rider.newcairo@shiplynow.local`, `rider.maadi@shiplynow.local`,
  `merchant@evechantelle.example`, `finance@shiplynow.local` (finance team).
- The starting data (3 dark stores, zones, 20 Eve Chantelle products, opening stock) loads on
  the first start. Later starts only add missing rows and never overwrite your changes.

### A month of demo activity (optional)

To show the dashboards, finance and reports with realistic numbers, add `DEMO_LOAD` = `true`
under **Environment** and redeploy. On that start, after the seed, the container simulates the
last 30 days (about 600 orders from accept to delivery, failed and cancelled ones, cash
handovers, bank deposits, weekly payouts, storage fees, rent and fuel, a supplier bill,
last month's salaries and tax invoices, a return and damage reports) through the real rules,
with the times of that month. It runs in the background after the app starts (background jobs are paused until `DEMO_LOAD` is false again), runs only once
(a later start sees it is loaded and skips it) and adds two demo merchants, Nile Pantry and
Bayt Home & Care, plus extra riders and a second finance approver, all with
`SEED_DEMO_PASSWORD`. Set `DEMO_LOAD` back to `false` afterwards. Locally:
`DEMO_LOAD=true pnpm db:demo`. Never use it on a database with real merchants.

### Starting from real data instead of demo data

When you are ready for real merchants and stock, set `SEED_ON_START` to `false` in Render
before loading real data, so no demo rows are added. Create a fresh Neon database (or a new
Neon branch) for production so staging test data never mixes with real stock.

### Fresh start: removing the demo data before real use (once)

Ledger, stock movements, order events and the audit log are append only, so demo data cannot
be removed by hand. The fresh start (`freshStart` in packages/db/src/fresh-start.ts) does it
once, in one transaction, right after the migrations and before the seed and the API start:

- **Kept:** dark stores and hubs with bins, hours and capacity; zones, area assignments and
  the area map (geo_areas, geocode cache); every setting except those of removed merchants;
  the HR structure (departments, grades, positions, document types, checklist templates,
  shifts, holidays); the chart of accounts (system and company accounts, store cash boxes) and
  the company profile; admin accounts with their access, store links and employee files; the
  merchant **Nabta** (by name or the shop getnabta.myshopify.com) with its users, products,
  Shopify store, app, locations, stock sync rows, Shopify data and the customers linked to it,
  and its (now empty) wallet.
- **Removed:** all orders, deliveries, photos and ratings; all stock (levels, bins, movements,
  shipments, counts, transfers, targets, returns, damage); the whole ledger and every finance
  document (handovers, payouts, requests, receipts, bills, suppliers, invoices and credit
  notes, bank statements, budgets, assets, recurring entries, salary runs); attendance;
  tickets, alerts, notifications, sent pushes and the audit log; every other merchant (Eve
  Chantelle, Nile Pantry, Bayt Home & Care...) with its users, products and Shopify data;
  every store staff, rider and finance user with their files; the four demo office admins
  (`demo.*@shiplynow.local`); geo suggestions; customers not linked to Nabta's store; the
  books lock.
- **Numbering starts again:** order numbers from SN100001; JV, PAY, CH, TCK, BILL, BS, INV,
  CN and RET numbers from 1 (they follow the rows that exist); EMP numbers continue after the
  kept admins' files.

Steps: take a Neon backup branch first. Add `FRESH_START` = `WIPE-DEMO-2026-11-07` under
**Environment**, make sure `DEMO_LOAD` is `false`, and deploy once. The log shows each table's
rows before and after (`[start] fresh start: orders 598 -> 0`). Then remove `FRESH_START`.
A row in `fresh_starts` records the run: a second run is refused, the demo loader refuses to
run, and the seed (`SEED_ON_START`) no longer adds the sample merchant, team or stock. If it
fails, the log says so, nothing changed, and the app starts as usual.

## Troubleshooting

| You see | Do this |
| --- | --- |
| `DATABASE_URL is not set` in the logs | Add it under the service's **Environment** tab and redeploy |
| `P1001: Can't reach database server` | Check the Neon string, keep `?sslmode=require` on the end |
| The page takes a minute to open | The free service was asleep; it wakes on the first visit |
| `Wrong email or password` for the admin | The admin is created once. Changing `SEED_ADMIN_PASSWORD` later does not change an existing admin's password |
